# ЙОМ — исключительно общественное мнение

React JS + Node.js/Express + PostgreSQL + Redis. Анонимная лента: публикации, комментарии, лайки, закладки, поиск, темы и свои сплетни в профиле.

## Локальный запуск

```sh
npm install
redis-server --bind 127.0.0.1 --save '' --appendonly no
# В другом терминале:
npm run dev
```

Открыть http://localhost:3000. Без DATABASE_URL используется PGlite (PostgreSQL в WebAssembly), данные в `.data/`. Redis обязателен. Если SMTP не настроен, только в development форма показывает тестовый код; письмо не отправляется и реальное владение почтой не проверяется. В production без SMTP регистрация возвращает ошибку.

## PostgreSQL и Redis в Docker

```sh
docker compose up -d
DATABASE_URL=postgres://iom:iom_local_password@localhost:5432/iom npm run dev
```

Локальный Redis и Docker Redis не запускайте одновременно на одном порту. Для SMTP задайте SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASS, SMTP_FROM, при необходимости SMTP_SECURE=true. Образец — `.env.example`. Файл `.env` из корня проекта автоматически загружается при `npm run dev`, `npm start` и `node server/index.js`, до подключения БД, Redis и SMTP. Переменные, уже заданные в окружении, имеют приоритет. Без `.env` сервер использует окружение и значения по умолчанию. После изменения `.env` перезапустите сервер. Требуется Node.js 20.12+ (рекомендуется установленная версия 20.20.2 или новее). Для HTTPS: COOKIE_SECURE=true.

## Регистрация и анонимность

1. Почта и хеш шестизначного кода записываются только в Redis на 10 минут. Пять неверных попыток удаляют заявку. Redis запускается без дискового сохранения.
2. Подтверждение атомарно удаляет заявку и создаёт пользователя с user_verified=true. API чтения и записи требует этого признака, в том числе для ранее выданных сессий.
3. Секретный случайный ключ показывается один раз. Сохраните его: почты в PostgreSQL нет, восстановление по ней невозможно. В БД хранится только SHA-256 хеш высокоэнтропийного ключа.
4. Повторный вход — по ключу. Имена, ники, пользовательские аватары и публичные идентификаторы авторов отсутствуют. Все авторы и комментаторы — «Пользователь»; список лайкнувших не выдаётся. Публичные ID публикаций и комментариев остаются для операций с контентом.
5. Внутренние users.id и foreign key нужны для связей и проверки владельца. Это анонимность между пользователями, а не отсутствие связей в серверной БД. Почтовый провайдер обрабатывает адрес доставки; содержимое самих публикаций пользователь выбирает сам.

Роли заданы PostgreSQL ENUM user_role: default, premium. Кнопка «Получить прем» в профиле бесплатно и идемпотентно меняет роль. Публичного премиум-значка нет. Прем позволяет начать временный личный чат и обезличить свою сплетню.

## Миграция прежнего MVP

При старте удаляются колонки name, handle, password, color. Старые пользователи получают user_verified=false, их сессии удаляются. Публикации и связи сохраняются. Старые аккаунты не переносятся в новые автоматически: требуется регистрация, старые публикации остаются анонимными и не присваиваются новому аккаунту.

## Проверки

```sh
npm test
npm run build
npm start
```

Тест требует redis-server в PATH, поднимает изолированный Redis на 6398, приложение на 3199 и временную БД. Проверяет подтверждение, удаление почты, повтор кода, закрытый доступ, отсутствие личных полей, ENUM, прем, повторный вход, лайки, комментарии и владение постами. Внешний PostgreSQL и реальная SMTP-доставка отдельно в этом окружении не проверены.

## Временные личные чаты

Премиум-пользователь начинает чат по ID сплетни или комментария. Сервер разрешает адресата внутренне; API возвращает только случайный ID чата, номер, тексты, время и признак «моё». Ответить может обычный пользователь. Получатель может быть офлайн и даже не иметь активной сессии. Чат ждёт его открытия раздела «Чаты»; первая сессия, открывшая приглашение, атомарно становится участником. До этого отслеживается только сессия отправителя. Писать самому себе нельзя. Пока получатель не пришёл, отправитель должен сохранять свою сессию открытой; завершение сессии по-прежнему удаляет переписку.

Переписка хранится только в Redis без сохранения на диск. Кнопка завершения удаляет чат у обоих. Выход из аккаунта и событие pagehide (включая перезагрузку страницы) удаляют все чаты этой сессии. При аварийном закрытии/потере сети heartbeat истекает через 45 секунд, очистка выполняется каждые 5 секунд. Фоновая приостановка вкладки тоже может завершить чат. В нескольких вкладках одной сессии закрытие любой завершает общие чаты. При повторном входе прежняя переписка не восстанавливается.

Время жизни ограничено также сроком авторизации обоих участников и 24 часами с создания; TTL Redis обеспечивает удаление даже при остановке сервера. Максимум 200 сообщений по 1000 символов. Это временные чаты, не сквозное шифрование; скопированные участниками сообщения отозвать нельзя.

## Обезличивание и структура сплетни

Премиум-автор может необратимо установить posts.user_id=NULL. Запись остаётся в ленте, но исчезает из собственных публикаций; право удаления и возможность связаться с автором теряются. Остальные связи (лайки, комментарии) не удаляются. Уже открытый чат живёт по своим правилам завершения и не хранит ссылку на исходную сплетню.

В публикации до 8 условных персонажей и до 10 событий, каждое с заголовком и текстом. Персонажи — публичные псевдонимы внутри истории; автоматического распознавания или замены настоящих имён нет. Интерфейс прямо предлагает использовать условные обозначения. Старые записи получают пустые массивы characters/events.
