# ЙОМ — исключительно общественное мнение

React JS + Node.js/Express + PostgreSQL + Redis. Анонимная лента: публикации, комментарии, лайки, закладки, поиск, темы и свои сплетни в профиле.

## Локальный запуск

```sh
npm install
redis-server --bind 127.0.0.1 --save '' --appendonly no
# В другом терминале:
npm run dev
```

Открыть http://localhost:3000. Без DATABASE_URL используется PGlite (PostgreSQL в WebAssembly), данные в `.data/`. Redis обязателен. Если SMTP не настроен, только в development форма показывает тестовый код; письмо не отправляется и реальное владение почтой не проверяется. В production без SMTP регистрация возвращает ошибку.

## PostgreSQL и Redis в Docker

```sh
docker compose up -d
DATABASE_URL=postgres://iom:iom_local_password@localhost:5432/iom npm run dev
```

Локальный Redis и Docker Redis не запускайте одновременно на одном порту. Для SMTP задайте SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASS, SMTP_FROM, при необходимости SMTP_SECURE=true. Образец — `.env.example`. Файл `.env` из корня проекта автоматически загружается при `npm run dev`, `npm start` и `node server/index.js`, до подключения БД, Redis и SMTP. Переменные, уже заданные в окружении, имеют приоритет. Без `.env` сервер использует окружение и значения по умолчанию. После изменения `.env` перезапустите сервер. Требуется Node.js 20.12+ (рекомендуется установленная версия 20.20.2 или новее). Для HTTPS: COOKIE_SECURE=true.

## Регистрация и анонимность

1. Почта и хеш шестизначного кода записываются только в Redis на 10 минут. Пять неверных попыток удаляют заявку. Redis запускается без дискового сохранения.
2. Подтверждение атомарно удаляет заявку и создаёт пользователя с user_verified=true. API чтения и записи требует этого признака, в том числе для ранее выданных сессий.
3. Секретный случайный ключ показывается один раз. Сохраните его: почты в PostgreSQL нет, восстановление по ней невозможно. В БД хранится только SHA-256 хеш высокоэнтропийного ключа.
4. Повторный вход — по ключу. Имена, ники, пользовательские аватары и публичные идентификаторы авторов отсутствуют. Все авторы и комментаторы — «Пользователь»; список лайкнувших не выдаётся. Публичные ID публикаций и комментариев остаются для операций с контентом.
5. Внутренние users.id и foreign key нужны для связей и проверки владельца. Это анонимность между пользователями, а не отсутствие связей в серверной БД. Почтовый провайдер обрабатывает адрес доставки; содержимое самих публикаций пользователь выбирает сам.

Роли заданы PostgreSQL ENUM user_role: default, premium. Публичного премиум-значка нет. Прем позволяет начать временный личный чат и обезличить свою сплетню.

## Подписка на прем

В профиле «Оформить прем» → выбор тарифа (неделя, месяц, 3 месяца, 6 месяцев, год) → ввод кода подтверждения. Пока оплаты нет, код у всех одинаковый: `123456` (переопределяется переменной PREMIUM_CODE). Тарифы — `server/premium.js`, список отдаёт `GET /api/premium/plans`, активация — `POST /api/premium` с `{plan, code}`.

- `users.premium_until` — дата окончания према. Покупка при активном преме продлевает текущий срок, после истечения — отсчитывается от текущего момента. Параллельные покупки не перекрываются (блокировка строки).
- `subscriptions` — история оформлений: тариф, начало и конец срока.
- Прем действует, только пока `premium_until > NOW()`: при каждом запросе роль вычисляется по дате, поэтому доступ пропадает сразу после окончания срока. Раз в минуту и при старте сервера роль в БД сбрасывается в default у истёкших подписок; дата окончания сохраняется.
- Прем без даты окончания (выданный прежней бесплатной кнопкой) при старте снимается.
- Пять неверных кодов подряд замораживают оформление для аккаунта на час (Redis, `iom:premium-attempts:<хеш>`), даже для верного кода. Успешная активация сбрасывает счётчик.
- Клиент сам перечитывает профиль в момент окончания према, без перезагрузки страницы.

## Документы, согласия и жалобы

Документы — страницы `/rules` (правила платформы), `/privacy` (политика конфиденциальности), `/consent` (согласие на обработку персональных данных). Тексты в `client/src/Legal.jsx`. Перед публикацией заполните плейсхолдеры OPERATOR (ФИО или наименование оператора, ИНН) и SERVER_LOCATION. Тексты — прототипы, их должен проверить юрист.

При регистрации нужно отметить три пункта: правила (и возраст 18+), политику и согласие на обработку данных. Сервер без них не отправляет код. Версия документов и время принятия сохраняются в `users.terms_version` и `users.terms_accepted_at`. При изменении документов обновите `termsVersion` в `server/auth.js` и `LEGAL_DATE` в `client/src/Legal.jsx`.

Жалоба на сплетню или комментарий (категория и необязательный комментарий) и обращение в поддержку отправляются письмом на SUPPORT_EMAIL (по умолчанию g652219@yandex.ru; адрес также указан в `client/src/Legal.jsx`) с темой `[Жалоба] от user_id N` или `[Поддержка] от user_id N`. Письмо жалобы содержит копию текста. На платформе жалобы не хранятся. Лимит — 10 обращений в час на аккаунт. Без SMTP в development письмо выводится в консоль сервера.

Сплетня — до 2000 символов, комментарий и событие — до 1000. Шрифт Manrope раздаётся с сервера (`@fontsource/manrope`), сторонних запросов у страницы нет.

## Миграция прежнего MVP

При старте удаляются колонки name, handle, password, color. Старые пользователи получают user_verified=false, их сессии удаляются. Публикации и связи сохраняются. Старые аккаунты не переносятся в новые автоматически: требуется регистрация, старые публикации остаются анонимными и не присваиваются новому аккаунту.


Тест требует redis-server в PATH, поднимает изолированный Redis на 6398, приложение на 3199 и временную БД. ## Временные личные чаты

Премиум-пользователь начинает чат по ID сплетни или комментария. Сервер разрешает адресата внутренне; API возвращает только случайный ID чата, номер, тексты, время и признак «моё». Ответить может обычный пользователь. Писать самому себе нельзя.

Переписка хранится только в Redis без сохранения на диск и никогда не попадает в PostgreSQL. Чат привязан к сессиям входа участников, а не к открытой вкладке:

- У чата два места: отправителя и получателя. Место отправителя держит его сессия. Место получателя сначала держат все его действующие сессии; первая, открывшая «Чаты», занимает место.
- Чат живёт, пока хотя бы одна сессия-держатель действует (не было выхода и не истёк срок). Закрытие вкладки, перезагрузка и фоновый режим телефона чат не завершают.
- Если участник вышел, чат остаётся у собеседника. При следующем входе новая сессия того же аккаунта занимает освободившееся место и видит всю переписку, включая ответы, пришедшие без него. Другая сессия того же аккаунта не может забрать место, пока прежняя ещё действует.
- Чат удаляется, когда не осталось ни одной действующей сессии-держателя (проверка при выходе и каждые 5 секунд), кнопкой «Завершить и удалить» у обоих или через 24 часа после создания (TTL Redis, срабатывает и при остановленном сервере). Если у получателя нет ни одной сессии и отправитель вышел, чат удаляется.

Действующие сессии отмечаются в Redis ключами `iom:session:<sha256 токена>` со сроком жизни сессии; выход удаляет ключ. Изменения чата атомарны (compare-and-set), параллельные сообщения не теряются. Максимум 200 сообщений по 1000 символов. Это временные чаты, не сквозное шифрование; скопированные участниками сообщения отозвать нельзя.

## Обезличивание и структура сплетни

Премиум-автор может необратимо установить posts.user_id=NULL. Запись остаётся в ленте, но исчезает из собственных публикаций; право удаления и возможность связаться с автором теряются. Остальные связи (лайки, комментарии) не удаляются. Уже открытый чат живёт по своим правилам завершения и не хранит ссылку на исходную сплетню.

В публикации до 8 условных персонажей и до 10 событий, каждое с заголовком и текстом. Персонажи — публичные псевдонимы внутри истории; автоматического распознавания или замены настоящих имён нет. Интерфейс прямо предлагает использовать условные обозначения. Старые записи получают пустые массивы characters/events.

## Развёртывание на сервере

Production-конфигурация: `Dockerfile` и `compose.production.yaml`. Приложение доступно через HTTPS на **3443**, внутренний порт **3010** привязан только к localhost; PostgreSQL и Redis доступны только внутри Docker-сети. Контейнеры автоматически запускаются после перезагрузки; данные PostgreSQL сохраняются в Docker volume.

В каталоге приложения нужны два файла, исключённых из Git, с правами 600:

- `.env.database`: `POSTGRES_USER=iom`, `POSTGRES_DB=iom`, `POSTGRES_PASSWORD` — случайный пароль.
- `.env.production`: `DATABASE_URL=postgres://iom:ПАРОЛЬ@db:5432/iom`, SMTP-настройки. Production Compose принудительно задаёт `COOKIE_SECURE=true` и `TRUST_PROXY=1`.

```sh
cd /opt/iom
docker compose -f compose.production.yaml up -d --build
docker compose -f compose.production.yaml ps
docker compose -f compose.production.yaml logs --tail=50 app
```

Исходники на сервере находятся в `/opt/iom`. Секреты не включаются в Docker-образ или Git. Локальная база данных при развёртывании не переносится. Резервные копии PostgreSQL нужно настраивать отдельно.

### HTTPS

Адрес: https://213.176.67.222:3443/ . Порт 443 занят существующим VPN и не изменялся. nginx проксирует запросы на 127.0.0.1:3010; порт 80 для этого IP обслуживает ACME и перенаправляет на HTTPS. Прямой HTTP-доступ на 3010 извне закрыт.

Сертификат Let's Encrypt на IP хранится в `/etc/letsencrypt-iom/live/iom-ip/`. Конфигурация nginx — `deploy/nginx-iom.conf`. Certbot 5.4 работает в отдельном контейнере; системный Certbot для других сайтов не изменён. `iom-cert-renew.timer` проверяет продление дважды в день, после успешной проверки nginx перечитывает сертификат. Unit-файлы находятся в `deploy/`.

```sh
systemctl list-timers iom-cert-renew.timer
systemctl status iom-cert-renew.service
```

`TRUST_PROXY=1` безопасен только при закрытом от внешних подключений backend и одном доверенном reverse proxy, как в этой конфигурации.
